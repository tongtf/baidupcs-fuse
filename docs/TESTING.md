# 测试设计与评审规范

> 适用范围：`baidupcs-fuse` 全部 Go 测试。
> 本规范是 `docs/TEST-COVERAGE-PLAN-2026-10.md` 的准入门槛：**先满足本规范，再谈覆盖率**。

---

## 1. 基本原则

1. **测试目的先行**：每个 `TestXxx` 上方必须有 `// 目的：...`，说明它验证的行为、状态迁移或失败语义。
2. **覆盖率是结果，不是目标**：禁止为了点亮语句而写“只调用、不断言”“只断言不 panic”的测试。
3. **测试真实流程**：优先覆盖“操作 → 状态变化 → 可观察结果”，而不是孤立调用内部小函数。
4. **一个测试只表达一个主题**：同一主题的多组输入用表驱动；不同主题拆成独立 `t.Run`。
5. **断言要能失败**：必须断言返回值、错误类型（`errors.Is/As`）、副作用（缓存、文件内容、请求次数、状态标记），不能只调用后结束。
6. **禁止重复覆盖**：同一分支已被真实流程覆盖时，不再为其单独写测试；发现重复应合并或删除。
7. **不测 trivial 代码**：纯 getter、无逻辑常量、标准库包装（如 `min`、`itoa`、路径拼接）不单独建测试，除非它承载安全/兼容性契约。
8. **测试名表达场景**：`Test<对象>_<场景>_<期望>`，避免 `TestFoo2`、`TestCoverageXxx`。

## 2. 必须覆盖的状态与边界

按被测对象选择适用项，不能只测 happy path：

| 类别 | 必须验证 |
|---|---|
| 状态机 | 初始态、合法迁移、非法迁移、重复操作（幂等）、关闭后操作 |
| 错误语义 | 错误类型/errno、错误是否被包装、失败后状态是否回滚、是否留下半成品 |
| 并发 | 单飞/去重、重复关闭、并发读写、取消传播、无数据竞争（`-race`） |
| 网络 | 成功、4xx、429、5xx、超时、ctx 取消、重试次数、请求体/头、幂等 |
| 缓存 | 命中/未命中、版本失效、容量淘汰、损坏恢复、跨账户隔离 |
| 文件系统 | 正常路径、边界偏移、越界、短读/短写、权限与类型不匹配 |
| 安全 | 路径穿越、注入字符、凭据不泄露、临时文件原子性 |

## 3. 禁止的测试写法

- ❌ `if err != nil { t.Fatal(err) }` 之后没有任何行为断言。
- ❌ `defer func(){ _ = recover() }()` 或只验证“不 panic”。
- ❌ 直接改内部字段来制造分支，却不验证对应的外部行为。
- ❌ 用 `time.Sleep` 作为唯一同步手段；必须用 channel、轮询+超时或注入时钟。
- ❌ 访问真实 `pan.baidu.com`/`pcs.baidu.com`；必须 `httptest` 或注入 fake。
- ❌ 为同一分支保留多个“复制粘贴”测试。
- ❌ 测试标准库或语言本身（如 `min(a,b)`、`strings.Join`）。

## 4. 测试结构模板

```go
// 目的：验证非空截断保留旧前缀，且 commit 后远端大小与内容一致。
func TestTruncate_Shrink_PreservesPrefix(t *testing.T) {
    // 1. 构造真实状态（远端旧内容 + staging）
    // 2. 执行用户操作
    // 3. 断言返回语义 + 远端/本地副作用
}
```

表驱动时，每个 case 必须有 `name` 和明确的 `want`；错误 case 断言具体错误，不断言“有错即可”（除非错误类型确实不构成契约）。

## 5. 评审清单

- [ ] 每个 Test 有“目的”注释。
- [ ] 至少一个断言会在实现被改坏时失败。
- [ ] 覆盖了该主题的主要失败路径，而不只是成功路径。
- [ ] 没有为覆盖率单独存在的测试。
- [ ] 测试之间无顺序依赖，可 `-shuffle=on -count=3`。
- [ ] 不访问真实网络/真实账号；外部依赖全部注入。
- [ ] 新增测试在 `-race` 下稳定通过。
